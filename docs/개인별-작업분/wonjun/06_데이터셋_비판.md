# 가상 공장 데이터셋 비판 — 실제 공장과의 유사성과 시험 용도 적합성

대상: `docs/datasets/manufacturing-mes-20261022/` — `vma_factory.json`(12라인·CNC 60), `vmb_factory.json`(16라인·CNC 96), `vmc_factory.json`(2공장·24라인·CNC 144), `company_references.json`, `README.md`.
용도: 공장 자산의 취약점(KEV)을 자산과 대조해 후보를 만들고, 패치 요청·승인·처리·검토를 시험·시연하는 자료.
방법: 3개 JSON을 직접 열어 수치를 계산하고, 서로 독립된 두 번의 비판 검토와 대조했다. 아래 수치는 모두 직접 계산한 값이며, 실제 제품 사양·지원 종료일은 확인하지 못한 경우 "확인 필요"로 두었다. 판단 구분: **[사실]** 데이터에서 계산한 값, **[도메인]** 현장 지식에 따른 판단.

## 1. 총평
자산 ID·IP·참조 무결성은 깨끗하다(끊긴 참조 0건, ID 중복 0건, 세그먼트 밖 IP 0건). 그러나 자산·통신·생산 데이터가 "종류별 개수 × 규모"로 찍어낸 복제라서, 같은 종류의 자산 사이에 차이가 없다. 패치 승인·보류·실패 시나리오와 KEV 매칭을 시험하는 데 필요한 이질성(벤더·버전·제약·소유자·노후도)이 거의 없고, 생산(MES) 데이터는 시간 규모와 정합성이 맞지 않는다.

## 3. 실제 공장이라면 있어야 하는데 빠진 것 (우선순위순)
1. 지원 종료(EOL) 일자와 레거시 OS(Windows 7/XP 임베디드, 구형 CNC 제어 PC)
2. 설비 제조사 원격 유지보수 접속과 외부 노출 표시(원격 작업 중계 서버 자산은 있으나 노출·접속 경로 필드가 없음)
3. 백신·EDR 설치 여부, 마지막 패치 적용일
4. 재부팅·정지 가능 시간대와 계획 정지(정비 창) 일정, 교대·가동·비가동 기록
5. 담당자 개인과 승인 권한자 구분
6. USB·이동매체, 엔지니어링 노트북, 협력사 PC
7. 펌웨어 버전, 빌드 번호
8. 쿨런트(절삭유) 공급·칩 처리 설비, 컴프레서·집진기·변전 모니터링 제어반
9. 품질 측정 설비(CMM 등), 공구 프리셋·공구 관리기, 현장 PDA·태블릿·무선 AP, 프린터·카메라·UPS, IO-Link 마스터
10. 설비 이질성(선반·머시닝센터·연삭 등)과 노후 설비 혼재, 폐기·예비·재고 자산
11. 서비스 통신(AD, DNS, NTP, 패치 서버, 백업, 로그)과 방화벽 정책·DMZ 경로
12. 건물·구역·랙 위치, 설치일, 보증·유지보수 계약
13. LOT 계보(원자재→반제품→완제품), 품질 결과, 정지 사유, 가동 이력(OEE), NC 프로그램·공구
14. 실제 현장 제어 프로토콜(제품별 지원 여부는 확인 필요)

## 4. 잘 만든 점 (공정한 비교용)
출처·라이선스·합성 표시와 "고장 라벨은 취약점이 아니다" 경고가 분명하고, 자산 ID·IP·모든 참조가 세 파일에서 일관된다. 원본 합성 데이터의 값은 보존되어 있다.

## 6. 마감 전에 고칠 수 있는 최소 개선 5가지
원본을 직접 고치기보다 **생성 스크립트(고정 난수)로 파생 파일을 만들어** 재현성과 원본 보존을 지킨다.

1. **자산 속성 편차 주입(약 1시간):** 5~10%의 자산에서 lifecycle(retired·spare), criticality `low`, 롤백 가능 여부 반전, patchConstraints에 `vendor_approval` 추가/제거를 바꾼다. 보류·재개·예외 승인 시험이 가능해진다.
2. **취약성 속성 4개 추가(약 1.5시간):** `supportEndDate`, `exposure`(internal·dmz·remote), `edr`, `rebootWindow`. 날짜는 공식 문서를 확인한 뒤 채우고, 모르면 비워 둔다. 일부 Windows 자산에는 빌드 번호를 넣는다.
3. **`lines.equipmentIds` 재계산(약 30분):** `equipment.lineId`로 다시 만들어 132/192/288개를 모두 연결하고 일치 검사를 추가한다.
4. **작업지시·관측 정리(약 1.5시간):** 미시작 작업지시의 관측을 진행·완료 쪽으로 옮기고, 계획 수량을 7품번에 맞춰 다양하게 하며, 작업지시 수를 회사 규모에 비례시킨다. 관측 시간 창을 하루로 넓히는 것은 선택이다.
5. **오염 변형 확장과 충돌 행(약 2시간):** 유형마다 변형 3개 이상, 같은 자산이 두 파일에 서로 다른 값으로 있는 충돌 행 30~50개, 파일을 자산 종류별로 나눈다. `quality_truth`에 대응 항목을 넣는다.

보너스: 회사별 고유 이질성 하나씩(예: VMA 구형 Windows, VMB 노후 가상화 호스트, VMC 이기종 방화벽), CNC당 HMI PC를 라인당 1~2대로 줄이고 DNC·공구 프리셋 PC 추가.

## 7. 용도에 미치는 영향 요약
- KEV 매칭 시험: 서버·PC·방화벽·가상화 쪽은 후보가 나오지만 OT 장비는 버전 공백 때문에 후보 0건이다. 같은 제품·버전 자산이 대량으로 같아서 묶음 확인 시험에는 오히려 유리하다.
- 패치 요청 흐름 시험: 자산 속성 편차가 없어 승인·보류·실패 시나리오를 만들려면 편차 주입(개선 1)이 먼저 필요하다.
- 시연 설득력: 생산 데이터(56분 슬라이스·수량 240 고정)를 앞세우면 현장 담당자 질문에 막힌다. 자산·네트워크 쪽을 중심으로 보여 주는 편이 안전하다.
