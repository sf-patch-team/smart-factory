# smart-factory — IA · UJ · PRD 정리

상태: 검토용 초안 · 고객 검증·팀 최종 합의 전

## 한눈에 보기

괄호는 `03a_PRD_보충.md`의 근거 절이다(양식에 맞춘 본문은 `03_PRD.md`).

- **정의:** 공장 자산의 취약점 조치를 **요청 → 승인 → 처리·근거 제출 → 관리자 검토**까지 한 요청에 연결해 기록하는 웹앱이다. 패치를 대신 실행하지 않는다. (03a_PRD_보충 1절)
- **사용자:** 요청·처리·근거 제출을 맡는 담당자(member), 승인과 완료 근거를 검토하는 관리자(admin). (03a_PRD_보충 2절)
- **핵심 문제(검증 전 가설):** 완료 회신을 받아도 자산별 조치 내용과 검증 근거가 연결되지 않아 대장·요청·작업 기록을 다시 대조해야 할 수 있다. 발생 빈도와 손실은 아직 측정하지 않았다. (03a_PRD_보충 1절)
- **첫 버전(필수 15개):** Google 로그인(member/admin), 최소 자산 입력·요청 전 수정, KEV 한 소스의 저장·조회, 후보의 사람 확인, 요청·승인·근거 제출·전체 기록 조회. 가상 자산 한 건으로 CUJ-1~5를 끝낸다. FR-15·20·40·41·42는 후속이다. (03a_PRD_보충 0·4절)
- **하지 않는 것:** 실제 장비 접속, 자동 패치, 호환성 자동 판정, NVD 필수 연동, 자동 알림, 외부 협력사 계정, 다단 승인, 대량 성능 시험. (03a_PRD_보충 6절)
- **지킬 규칙:** ① 요청자·처리자와 같은 사용자는 승인과 완료 검토를 할 수 없다. ② 승인 전 처리·중복 활성 요청·권한 밖 조회/변경은 서버에서 거부하고, 제출한 근거는 잠근다. (03a_PRD_보충 4·5절)
- **구현 상태:** 앱·DB 기준 QA는 모두 No Run이다. 도메인 규칙과 가짜 저장소의 단위 시험 50개 통과·1개 보류(todo)다. 화면은 뼈대, 저장은 메모리 시험 구현이다. **DB 접근 규칙에 결함이 있어 수정이 필요하다.** (03a_PRD_보충 7절)
- **확인 대기:** 국내 현장 검증, 제출 일시·공개 범위·문서 통합 허용, 인증·운영 설정, 최초 관리자 지정 대상, 공수의 실제 측정(초도 추정 88~148인시). (03a_PRD_보충 7·9절)
- **제안(팀 미채택):** 협력사·내부 타 팀 승인이 필요한 패치는 요청에 외부 승인 항목을 두고, 빠지면 내부 승인을 막는다. 시스템 관리자 역할은 후속. (03a_PRD_보충 10-1절)
- **범위 밖(후속 검토):** 구조도, 빠른 현장 등록, 자산 이동, 혼합 제조사 특화, 일정 조율 시스템, 제조사 API 수집, AI 호환성 검토.
