## 2. 고객 여정 지도: 취약점 인지 → 조치 완료 (PS-1 중심)
| 단계 | 접점(화면) | 행동 | 기존 방식의 불편 | 감정 기존→새 | 기회 |
|---|---|---|---|---|---|
| 1. 인지 | DB-01-P | 보안 공지를 확인 | 메일·뉴스 여러 경로, 중복 확인 | -2 → +1 | 상위 위험 5건만 한 화면 |
| 2. 해당 여부 판단 | RK-02-T, RK-05-M | 우리 자산과 대조 | 엑셀과 눈으로 대조 | -2 → +1 | 매칭 후보 + 사람 확인 |
| 3. 우선순위 | RK-03-T, RK-04-P | 무엇부터 할지 정함 | 기준 없음, 근거 설명 어려움 | -1 → +1 | 점수 + 점수 구성 |
| 4. 호환성·요청 | RQ-02-P | 벤더·시험·되돌리기 확인 후 신청 | 메일로 벤더 확인, 기록 흩어짐 | -2 → 0 | 체크리스트 한 번에 |
| 5. 승인 | RQ-03-P, AD-02-P | 관리자 결재 | 근거 없이 미룸, 승인 늦음 | -2 → +1 | 근거·영향 설비 동봉 |
| 6. 처리·기록 | RQ-04-M, RQ-05-M | 적용 또는 보류·완화 | 결과가 메일에 남음 | -1 → +1 | 상태 이력 자동 기록 |

**감정 곡선**(기존): -2 · -2 · -1 · -2 · -2 · -1 → (새) +1 · +1 · +1 · 0 · +1 · +1. 가장 낮은 곳은 2·4·5단계(해당 여부 판단, 호환성 확인, 승인 대기)이고, 여기가 핵심 설계 대상이다.

**인사이트**
1. 병목은 패치 자체보다 **판단·확인·승인 대기**다. (가설 H1·H2)
2. 사용자의 일이 "찾기·대조"에서 "시스템이 제안 → 사람이 OK"로 바뀌는 곳이 매칭 후보 확인이다.
3. "못 함"이 정상 상태이므로 보류·완화 조치가 **정식 경로**여야 한다. (H1·H7)

## 5. 측정 계획 (추후 KPI 연결)
- 모든 상태 변경에 **시각·행위자·사유**를 저장한다(ERD에 반영).
- KPI 후보: 요청→완료 소요 시간 · 승인 소요 시간 · 기한 초과율 · 보류율 · 반려율 · 후보 확인율.
- 현재값은 "측정 전"이고, 시험 데이터로 계산 방법만 먼저 검증한다.
