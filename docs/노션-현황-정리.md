## 1. 한 줄 요약
공장 설비·IT 자산 중 **지금 위험한 취약점**을 찾아 패치를 요청·승인·처리·기록하는 웹앱. 실제 악용 취약점 목록(CISA KEV)과 **가상 공장 자산 115개**를 맞춰 보고, 점수·근거와 함께 보여 준다. 설비는 "지금 패치 못 함"이 흔해서 **호환성 확인 · 완화 조치 · 보류(사유·재검토일)**를 정식 경로로 둔다.

## 2. 핵심 결정
| 결정 | 내용 | 이유 |
|---|---|---|
| 주제 | 자산 취약점 패치 관리 (KEV 기준) | 데이터가 단순, 키 승인 대기 거의 없음 |
| 매칭 | 시스템이 후보를 만들고 **사람이 확인**(ADR 0001) | KEV에 버전 정보가 없어 자동 판정은 오류 가능 |
| 호환성 | 앱이 판정하지 않고 **체크리스트로 확인**(ADR 0002) | 공개 데이터에 호환 정보 없음 |
| NVD | 1차에서 제외(ADR 0003) | 키·호출 한도 위험, 마감 |
| 후보 폭증 대응 | 같은 제품·버전 **묶음 확인** + 상위 N건 표시 | 실제 KEV와 맞추면 후보 6,780건 → 묶음 651건 |
| 스택 | Next.js · Supabase · Vercel | 로그인·DB·권한 내장 |
| DB | 사용자 본인 Supabase `smart-factory`(서울), 표 11개 | 사용자 승인 |
| 협업 | 팀원 3명만 GitHub 협업자, 강사는 추가 안 함 | 사용자 결정 |
| 개발 방식 | 3명 동시 병렬(바이브 코딩), PR로만 합침 | 마감 5일 |

## 6. 서버 키(secret) 받는 방법
앱이 KEV를 DB에 저장하려면 서버 전용 키가 필요하다. 자동으로 가져오는 것은 권한 검사에서 막혀서 **직접 복사**해야 한다.
1. Supabase 대시보드 → `smart-factory` 프로젝트 → **Project Settings → API Keys**
2. **Secret key**(`sb_secret_…`) 또는 Legacy의 `service_role`을 복사
3. 프로젝트 `.env.local`의 `SUPABASE_SERVICE_ROLE_KEY=` 뒤에 붙여 넣기(저장소·채팅·PR에 쓰지 않는다)
4. Vercel 배포 때 같은 이름의 **서버 환경변수**로도 넣기. 팀원에게는 주지 않는다(A만 보관)

## 7. 위험과 주의
| 위험 | 대비 |
|---|---|
| 후보가 너무 많음(알람 피로) | 묶음 확인 · 상위 N건 · 필요 시 최근 N개월 필터 |
| 인터뷰가 가상 가설 | 실제 인터뷰 기록, 발표에서 가설이라고 명시 |
| BPI는 실제 회사의 IT 기록 | 통계 분포만 사용, 원본·이름 미사용, 출처 표기(`docs/data-sources.md`) |
| 공장 설비 기록이 아님 | PLC 등은 BPI에 대응 유형이 없어 hardware 수치를 임시 사용(우리 가정) |
| 같은 파일 충돌 | 폴더 소유·계약 파일·소 PR·매일 밤 통합 |
| 일정 지연 | 줄이는 순서: 통계·EPSS → 이력 화면(Could) → 대시보드 부가 → 모바일 카드 |
| 키 노출 | 서버 키는 A만, 채팅·저장소에 값 남기지 않음 |
