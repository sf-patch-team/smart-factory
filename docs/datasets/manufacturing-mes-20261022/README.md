## 구조와 사용법

각 JSON은 독립된 회사 데이터셋이다. 아래 배열의 id와 참조 ID로 연결한다.

|키|내용|
|---|---|
|company / summary|가상 회사와 수량 요약|
|canonical_assets|정리된 기준 자산. 모르는 펌웨어는 null|
|equipment / lines|물리 설비와 공정 라인|
|network_segments|공장별 VLAN·관리 IP 구역|
|application_flows|허용을 가정한 논리 통신|
|line_port_bindings|라인 단말의 스위치 포트 배정 가정|
|software_installations|자산별 소프트웨어·펌웨어 식별 설정|
|mes_work_orders / mes_lots|가상 생산지시와 LOT|
|machine_observations|원본 AI4I 행과 가상 설비·LOT 연결|
|raw_asset_register|부서별 엑셀·협력사 대장을 모사한 오염 입력|
|quality_truth|입력 행과 기준 자산의 정답 연결·심은 오류|
|raw_mes_exceptions|ERP·MES 생산지시 번호 불일치 예제|
|sources|출처·라이선스·원본 해시|

업무 PC 수는 관리 대상으로 포함한 가정이며 임직원 수와 1:1이 아니다. 인력·규모는 대형 업체 시나리오일 뿐 업계 평균이나 실제 회사 추정치가 아니다. 각 공장에 MES 앱 2대, DB 1~2대, OPC 2대, SCADA 2대, 공정 이력·ERP·QMS·WMS·API·백업·인증·가상화 시스템을 배치했다. 소프트웨어 벤더 조합과 버전은 설치·호환성 검증을 거치지 않은 테스트 설정이다.

## 네트워크와 MES 관계

라인 제어기·HMI → 엣지 수집 → OPC·SCADA → MES 앱 → MES DB. ERP는 산업 DMZ의 API 서버를 통해 생산지시·실적을 연계한다. 사무·공장운영·MES·DB·관리·백업·DMZ·라인별 구역을 분리했다. 이는 관리 IP와 논리 통신 모델로 실제 결선·스위치 포트 용량·방화벽 정책·가용성 설계를 인증하지 않는다.

같은 제품·릴리스의 중복 설치는 정상이다. 같은 자산의 여러 대장 행은 중복 후보다. IP 비교는 공장·VLAN·관측 시점을 함께 봐야 한다. MES 앱·DB의 복수 인스턴스가 있다는 사실만으로 HA가 구현됐다고 간주하지 않는다.

라인당 스위치 2대의 단말 포트 배정은 16포트 장비 EDS-516A를 가정하고 15·16번은 업링크용으로 비웠다. 포트 중복·범위를 검사했으나 건물 전체의 물리 결선·이중화 경로는 모델 범위 밖이다. 기존 설비를 포함한 재고 시나리오이며 신규 장비 구매 추천이 아니다. 사양 참고: https://www.moxa.com/en/products/industrial-network-infrastructure/ethernet-switches/layer-2-managed-switches/eds-516a-series

## 더러운 원본의 구성

빈 버전, 제조사 대소문자·공백, 제품 약어, 퇴사 담당 코드, 잘못된 IP, 이설 전 라인, 오래된 확인일, 시리얼 누락, 폐기·가동 충돌, 엑셀식 버전 표기, 자유 메모, 예전 IP, 중복 대장, IP 충돌, ERP·MES 번호 불일치를 심었다. 오류율은 테스트 강도를 위한 임의 가정이고 실제 산업의 통계가 아니다. quality_truth는 화면 입력이 아니라 QA 정답으로 분리해서 쓴다.

원본 null을 안전·최신·해당 없음으로 치환하지 않는다. IP·소유자·상태 충돌은 자동 덮어쓰기보다 근거 확인 대상으로 다룬다. 개인정보·계정 비밀·실제 회사 주소는 포함하지 않았다. 모든 IP는 가상 사설망 값이며 외부 연결 코드는 없다.

## 검증과 작업 기록

2026-10-22: 사용자 다운로드 ZIP을 읽고 SHA-256 기록, 원본 10,000행의 값 보존과 중복 없는 분할 확인. 기준 자산 ID·관리 IP의 구역 내 유일성, IP 대역, 소유자·설비·통신·가상화 호스트·MES·LOT 참조, JSON 재열기 검증을 실행했다. 오염은 raw 계층에만 심었다. 앱·DB·기존 시드·명세·배포는 변경하지 않았다. 실제 장비·네트워크·MES 연동은 미실행.

앱에 자동 적재하는 포맷은 아직 아니다. canonical_assets는 기존 Asset보다 확장된 필드와 null 버전을 포함하므로 검토·변환이 필요하다. 실제 KEV 해당 여부는 별도 검증해야 한다.

기업의 제품 분야만 공식 자료에 근거했다. 규모 순서, 실제 MES 도입, 설치 벤더·버전·IP·취약점·관리 미흡 여부를 확인한 자료가 아니다. 기존 자산 수·인원·공장 수를 실제 회사 수치로 인용하지 않는다.

프로젝트 중심은 MES·SCADA 서버, HMI·엔지니어링 PC, 네트워크 장비의 보안 패치 요청→승인→처리→검증→완료 기록이다. PLC·CNC 펌웨어는 벤더 지원·호환성·정비조건을 확인한 뒤 다룬다. SIM-MES 같은 가상 제품에 실제 CVE를 붙이지 않는다. 기반 운영체제·소프트웨어의 제품과 버전을 별도로 확인한다. AI4I 기계 고장은 보안 취약점이나 패치 실패의 증거가 아니다. 버전 불명은 확인 필요로 남긴다.

이번 작업은 참고 연결과 설명 추가이며 기존 3개 회사 JSON의 자산·오류·원본 관측 값은 바꾸지 않았다. 앱·DB·실제 장비 변경 없음. 에고 라이트 bootstrap 연결 실패로 공식 자료는 웹 검색·열람으로 확인했다.
