# UJ — 사용자 여정과 핵심 과업

상태: 검토용 초안 · 화면 ID는 01_IA.md 기준

## 여정 요약

- **고객 여정 5단계:** 공지 확인 → 대상 확인 → 요청/검토 → 처리 또는 보류 → 결과 확인.
- **CUJ-1 후보 확인:** 담당자가 자산·KEV 후보의 적용 범위를 검토하고 판단 근거를 저장한다. 미확인과 확정이 구분되어야 성공.
- **CUJ-2 요청→완료:** 담당자 신청 → 관리자 승인 → 담당자 처리·근거 제출 → 관리자 검토 후 완료. 승인 전 처리와 자기 요청 승인이 막혀야 성공.
- **CUJ-3 보류·재검토:** 담당자가 사유·완화 조치·재검토일을 남기고 목록 필터로 확인한다. 같은 ID 재승인 규칙은 후속이다.
- **CUJ-4 이력 열람:** 관리자가 자산·기간·사용자·요청으로 조회해 누가 언제 무엇을 근거로 바꿨는지 추적한다.
- **CUJ-5 데이터 신뢰:** 받은 시각·성공/실패를 보고(시험 모드 표시는 후속) 오래된 자료·실패·후보 없음을 혼동하지 않는다.
- **아직 비어 있는 것:** 단계별 감정·소요 시간·개선 정도 관찰, 5개 과업의 실제 실행 시험, 자산 편집 전후 이력(후속).

## 여정과 핵심 과업

고객 여정의 단계는 공지 확인→대상 확인→요청/검토→처리 또는 보류→결과 확인이다. 기존 대장·게시판·메일 사이를 오가던 확인을 연결하는 것이 기회다. 단계별 감정·시간·개선 정도는 아직 관찰하지 않았으므로 점수나 개선 곡선을 만들지 않는다.

| CUJ | 사용자 행동 → 시스템 반응 | 성공 기준·중요 순간(MOT) | 예외와 복구 / 화면 |
|---|---|---|---|
| CUJ-1 후보 확인 | 담당자가 자산·KEV 후보의 제품과 적용 범위를 검토 → 해당/해당 없음·근거 저장 | 미확인과 확정 구분, 판단 근거 확인 가능 | 버전 미상·자료 부족은 미확인 유지, 자산 보완으로 이동 / AS-03-P, RK-01-P, RK-04-P, RK-05-M |
| CUJ-2 요청→완료 | 담당자 신청 → 관리자 승인/반려 → 담당자 처리·근거 제출 → 관리자 내용 검토·수락 후 완료 | 승인 전 처리·자기 요청 승인 불가. 자산·적용 내용·검증 결과·검토 기록 연결 | 보완 요구는 처리 중 유지, 작업 실패·취소·완료 후 오류는 PRD 5절 경로 / RQ-02-P, AD-02-P, AD-07-P, RQ-03-P, RQ-04-M |
| CUJ-3 보류·재검토 | 담당자가 사유·완화 조치·재검토일 입력 → 요청 목록에서 보류/재검토 대상 필터·기한 도래 문구 조회 | 담당자·관리자가 목록을 직접 확인. 실패 없는 보류만 같은 ID 재승인, 실제 작업 실패는 복구 확인→실패 종료→새 요청 | 자동 통지 없음. 목록 확인을 놓칠 위험은 첫 버전 한계 / RQ-05-M, RQ-01-P, RQ-03-P, AD-02-P, AD-07-P |
| CUJ-4 이력 열람 | 관리자가 자산·기간·사용자·요청으로 조회 → 판단 당시 정보·처리 결과·상태 이력 표시 | 누가 언제 무엇을 근거로 바꿨는지 추적 | 권한 외 접근 거부, 결과 없음 안내 / AS-03-P, AD-03-P, AD-04-P, AD-07-P |
| CUJ-5 데이터 신뢰 | 사용자가 위험 목록에서 받은 시각·성공/실패 확인(시험 모드 표시는 후속) → 필요 시 관리자 데이터 화면에서 재시도 | 오래된 자료·실패·후보 없음의 의미를 혼동하지 않음 | 실패 시 이전 정상본 유지, 재시도 후 상태 갱신 / RK-01-P, AD-05-P |

위 CUJ-1~5는 첫 버전 기준이다. CUJ-4의 이력은 요청·판단·근거 이력이며 자산 편집 전후 이력은 후속이다. **후속 여정 확장**은 DB-01-P/AD-01-P 집계→목록 이동, 자동 알림 수신→해당 요청 이동이다. 첫 버전 성공 조건에 대시보드·자동 알림을 포함하지 않는다. UJ 검증은 이후 QA에서 정상·오류 경로로 실행한다. 현재는 여정 설계만 완료했으며 5개 과업을 실행 통과했다고 표시하지 않는다.
