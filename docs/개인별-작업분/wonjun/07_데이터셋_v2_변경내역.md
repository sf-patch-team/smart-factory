# 가상 공장 데이터셋 v2 — 변경 내역

원본(`docs/datasets/manufacturing-mes-20261022/`)은 그대로 두고, `dataset-v2/generate_v2.py`가 **파생 파일**을 만든다. 모든 변형 값은 시험용 가정이며 실제 회사·장비의 사실이 아니다.

## 만드는 법
```
cd dataset-v2
python generate_v2.py <원본 폴더> out research_versions.json product_catalog.json
python render_report.py out ../07_데이터셋_v2_변경내역.md
python export_xlsx.py out out/dataset_v2.xlsx   # 보기 쉬운 엑셀(정답지 시트 포함이라 저장소에는 올리지 않음)
```
같은 시드(20261024)면 같은 결과가 나온다. 결과는 회사마다 두 파일이다: `*_factory_v2.json`(자산 데이터)과 `*_expected_matches.json`(정답지). 결과 파일(약 10MB)은 저장소에 넣지 않는다. 아래 "생성 결과 수치"는 `render_report.py`가 결과 파일에서 세어 채우므로 손으로 고치지 않는다.

## 자산 데이터와 정답지의 분리
**자산 데이터(`*_factory_v2.json`)**에는 장비 정보만 있다: 제조사·제품·버전(`patchLevel`, 필요하면 `osBuild`·`firmwareVersion`), 도입 연도(`installedYear`), 지원 종료일(`supportEnd`, 단종은 `discontinuedOn`), 중요도 등. 취약점 판정·EPSS·CVSS는 **넣지 않는다.** 앱의 수집기가 새 공지를 받을 때 계산하는 값이기 때문이다. 자산에는 가상 표시(`scenario`, `scenarioNotice`, `fieldProvenance`)만 붙고 공지·CVE는 없다.

**정답지(`*_expected_matches.json`)**는 자산의 제품·버전을 공개 공지와 비교한 기대 결과다. 자산 목록과 별개의 시험 자료이며 앱이 읽지 않는다. 수집기가 낸 결과가 맞는지 QA에서 비교하는 용도다. 가상 자산 ID와 실제 CVE가 함께 있으므로 저장소에 올릴지는 팀이 정한다(현재 올리지 않음). 장비에 넣을 실제 버전 후보와 공지는 `product_catalog.json`(데이터 파일일 뿐 별도 기능이 아님)에서 가져온다. 장비에 들어간 버전 번호는 실제 공개 번호를 가정해 배정한 값이고 회사·공장·자산은 가상이다. 자산마다 도입 연도(2018~2025)를 가정하고 지원 종료 연도를 넘지 않게 하며, 후보 중 하나를 배정한다.

연결한 제품(카탈로그 항목 15개): FortiOS, PAN-OS, Cisco Catalyst 9300, Windows 10 22H2·IoT LTSC 2021·Windows 11 23H2, Windows Server 2019·2022, ESXi(6.7·7.0), Veeam 12, SIMATIC S7-1500, SINUMERIK 840D sl, MELSEC iQ-R R04CPU, FANUC R-30iB Plus, Moxa EDS-516A.

정답지의 판정:

| 판정 | 뜻 |
|---|---|
| affected_scenario | 그 버전을 쓴다고 가정하면 영향 범위, 수정 버전 있음 |
| affected_conditional | 영향 범위이나 기능 전제(예: SSL-VPN 사용)가 맞을 때만 해당. `precondition`에 조건 |
| affected_no_fix | 영향 범위인데 제조사가 수정 계획이 없다고 함 |
| fixed | 수정 버전 이상 |
| not_listed | 공지의 영향 목록에 없는 계열·버전 |
| unknown | 영향 범위이나 수정 버전을 확인하지 못함 → 확인 필요 |

정답지의 항목마다 `cvss`(점수·버전·출처), `epss`, `confidence`(근거가 제조사 원문·MSRC면 high, KEV 파일+페이지 요약이면 medium, 요약만이면 low), `scenario: true`가 붙는다.

- **EPSS는 실제 값이 아니다.** 실제 값을 가져올 수 없어 시험용 값을 만들었고 `synthetic: true`로 표시한다. KEV 등재 건은 높게 둔다.
- KEV 여부는 CISA 파일(2026-10-23판)과 직접 대조했다. 제어기(Siemens·Mitsubishi·FANUC·Moxa) CVE는 모두 KEV에 없다. '실제 악용됨'으로 표시하지 않는다.
- Cisco 후보 버전은 공지 수정 표·SMU 기준 버전·권장 릴리스에 실제 나온 번호만 쓴다(출처 없는 번호를 뺐다). 공지가 16.12 수정판을 Catalyst 3650·3850 한정으로 적어 9300의 16.12 계열은 `not_listed`다.
- 출시 연도는 계열(line) 단위로 대신했다. 제어기 펌웨어는 연도를 확인하지 못해 도입 연도와 무관하게 배정했다.
- `retired` 자산은 정답지에서 판정을 비우고 `spare`는 남긴다.
- 지원 종료 자산(`supportStatus: ended`)은 종료 뒤 빌드를 ESU 등으로 받는지 모델링하지 않았다. 확인 필요.
- 근거 보존: 버전 배정이 조사값(날짜·KB·확신 등급)을 덮지 않고 같은 번호면 가져온다.

## 서버 소프트웨어 조사(2026-10-24)
- 확인(원문 열람): KEPServerEX 영향·수정 버전(CISA 공지), Ignition 영향·수정 버전과 장기 지원 표(제조사 문서), WinCC V7.5 SP2 업데이트 수준(CISA 공지), Windows Server 2016·SQL Server 2017 종료일(Microsoft), RHEL 8·9 종료일(Red Hat API), Oracle 19c 종료일(Oracle 안내문, 일부 항목 상충).
- **KEV 대조:** 위 제품(LS, PTC Kepware, Ignition, Siemens WinCC, Rockwell, Matrikon, Prosys, OPC Foundation)의 CVE는 모두 CISA KEV(2026-10-23판)에 없다. '실제 악용됨'으로 표시하지 않는다.
- 확인 못 함: KEPServerEX·Matrikon·Prosys의 지원 종료·출시 연도, WinCC 공식 수명주기(포럼 글 요약뿐), FactoryTalk View SE 수명주기. MES 응용(가상 공급사)은 실제 제품이 아니라 판정 대상이 아니다.
- LS ELECTRIC: 인버터·HMI·출시 연도 조사는 하지 못했다. NVD 키워드 검색 결과 공지가 있는 것은 XGT PLC 계열(CVE-2022-2758)과 XBC-DN32U(2023년 7건)뿐이며 다른 공지가 없다는 증명은 아니다.

## 한계 (알고 둔 것)
- FR-A800: 공지가 FR-A800-E 등 변형 단위이고 번호 근거가 없어 제외. KEYENCE SR-2000: 공개 공지를 찾지 못함. FANUC 0i-MF Plus CNC, Windows Embedded Standard 7, Ubuntu·SQL Server·Moxa 외 일부 자산은 판정이 없다.
- 제어기 공지는 계열 단위(S7-1500 CPU 계열, iQ-R R04(EN)CPU)라 모델 대응은 확인 필요. Siemens·Mitsubishi 일부 공지 본문을 읽지 못함. Fortinet·ESXi·Veeam 영향 범위는 페이지 요약으로 읽은 값이라 사용 전 재확인 필요.
- ESXi 6.7의 CVE-2020-3992, Cisco CVE-2025-20352는 수정 빌드를 확인하지 못해 `unknown`.
- 제조사 비율(LS·Mitsubishi·Siemens 등), 라인 유형별 설비 수, 병목·이중화·승인 비율은 규칙 표(`v2_rules.py`)에서 정한 가정이다. 실제 공장의 분포를 반영하지 않으니 현장 경험에 맞게 고쳐야 한다. 이번에 넣은 제품 중 LS 인버터(LSLV-H100), Yaskawa YRC1000, Mitsubishi M80, FANUC 0i-MF Plus, Siemens SCALANCE XC208, Cisco IE-3300은 존재하는 제품 이름이지만 이 자료에서 이름·모델·버전을 검증하지 않았고 공지 판정이 없다. LS PLC(XGK-CPUU, XGI-CPUU, XBC-DN32U)는 CISA 공지·NVD에서 이름을 확인했으나 펌웨어 후보는 공지에 나온 경계 번호뿐이고 출시 연도는 확인 못 했다. Catalyst 9300을 코어 스위치로 쓴 것은 실제와 다르다(코어는 상위 기종). 오래 방치된 빌드의 분포도 단순하다.
- 누락: 소프트웨어 구성 목록(SBOM), 패치 적용 이력·티켓, 최근 스캔 일자, 부서별 SLA, 승인된 유예 예외.
- CNC–HMI 1:1 구조 분리, PDA·IO-Link 마스터·변전 모니터링·집진기는 추가하지 않음. 네트워크 오류(IP 충돌 등)는 대장 오염에만 반영.
