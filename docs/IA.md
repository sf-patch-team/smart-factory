# 정보 구조(IA): smart-factory

## 0. 문서 개요
- 문서 종류: **IA + 화면목록**(작은 서비스라 메뉴구조도는 4번 내비게이션 모델에 합침) · 독자: 팀원 3명, 평가자 · **신규 구축**(상태 라벨은 모두 `추가`라 생략)
- 연결: `Intent.md`(2026-10-22) · `GLOSSARY.md` · ADR 0001~0003 · 인터뷰 가설 H1~H8(`docs/01-momtest-인터뷰.md`)
- 가정: 역할은 담당자·관리자 2개. 관리자 지정은 DB에서 한다(화면 없음). 외부 협력사 역할·알림·NVD는 범위 밖.
- 화면 ID 규칙: `[메뉴 약자 2글자]-[번호 2자리]-[형태]` — 형태 `P` 페이지 / `M` 모달 / `T` 탭. ID와 화면명은 중복 금지, 삭제해도 ID는 재사용하지 않는다(행을 `삭제` 상태로 남긴다).

## 3. 내비게이션 모델 (메뉴구조도)
- **주 내비게이션(담당자)**: 대시보드 · 위험 항목 · 자산 · 패치 요청 (4개)
- **주 내비게이션(관리자)**: 위 4개 + **관리**(관리 대시보드 · 승인 대기 · 전체 자산 · 전체 이력 · 데이터 관리)
- **유틸리티**: 계정(로그아웃), 받은 시각 표시줄(모든 화면 상단 가까이)
- **모바일**: 하단 탭 4개(담당자), 관리자는 "관리"를 5번째 탭
- **Depth**: 모든 핵심 화면이 메인 기준 2 Depth 이내

## 4. 콘텐츠 위계

### 대시보드 (DB-01-P)
1. 지금 가장 위험한 위험 항목 상위 5건 — 판단이 목적이라 가장 먼저
2. 내 요청 현황(승인 대기·처리 중·보류) — 내가 할 일
3. KEV 받은 시각과 상태(읽음/내용 없음/못 읽음) — 데이터 신뢰
4. 확인 대기 후보 개수

### 위험 항목 상세 (RK-04-P)
1. 점수와 **점수 구성**(기한 초과 일수·랜섬웨어·중요도·최근 등록) — 왜 지금인지
2. 자산·영향 설비·패치 제약 — 가동에 미치는 영향(결재 근거)
3. KEV 취약점 정보(이름·설명·요구 조치·CVE) — 원문
4. 패치 요청 시작 버튼 / 확인 입력

### 요청 상세 (RQ-03-P)
1. 현재 상태와 다음에 할 사람
2. 호환성 확인 결과 요약
3. 상태 이력(누가·언제·무엇·사유)
4. 처리 결과, 보류 사유·재검토일

## 5. 사용자 흐름

### F1. 자산 등록 → 패치 완료 (담당자·관리자)
1. 담당자가 AS-01-P에서 AS-02-M으로 자산 등록
2. 시스템이 KEV와 대조해 RK-02-T에 **매칭 후보** 생성
3. 담당자가 RK-04-P에서 RK-05-M으로 **확인**
   - 해당 없음 → 후보 종료(이력 남김)
   - 해당함 → 위험 항목(RK-03-T)
4. 담당자가 RK-02-P에서 **호환성 확인** 체크리스트 작성 후 신청
5. 관리자가 AD-02-P → RQ-03-P에서 승인 또는 반려(사유)
6. 담당자가 처리 중으로 바꾸고 RQ-04-M에 결과 입력 → 완료

### F2. 패치가 맞지 않는 설비 (인터뷰 H1·H7)
1. F1의 4단계 체크리스트에서 "호환 안 됨/불명" 선택
2. 담당자가 **완화 조치** 또는 **보류**를 고르고 RQ-05-M에 사유 입력(보류는 재검토일 필수)
3. 관리자가 승인 → 재검토일이 되면 대시보드에 "재검토 필요" 표시

### F3. 외부 데이터 갱신 실패
1. 자동 갱신 실패 → 화면 상단에 **못 읽음** + 마지막 성공 시각 표시, 이전 데이터 유지
2. 관리자가 AD-05-P에서 수동 갱신

### F4. 감사 열람 (관리자, 인터뷰 H4)
1. AD-04-P에서 기간·사용자·요청별 필터로 상태 이력과 자산 변경 이력 열람

## 7. 용어 사전 (UI 라벨)
`GLOSSARY.md`와 같은 단어를 쓴다: 자산 · 매칭 후보 · 확인 · 위험 항목 · 우선순위 점수 · 패치 요청 · 호환성 확인 · 완화 조치 · 보류 · 상태 이력 · 받은 시각 · 담당자 · 관리자 · 시험 모드.
상태 라벨: **신청 · 승인 · 반려 · 처리 중 · 완료 · 보류 · 완화 조치** (색 + 글자로 함께 표시).

## 9. 콘텐츠 성장 계획
- KEV 항목(약 1,750개)과 이력은 계속 늘어남 → 목록은 점수 순 + 페이지 나누기, 위험 항목은 **상위 N건만 기본 표시**(인터뷰 H6).
- 이력은 필터(기간·요청·사용자)로 좁힌다.

## 10. URL 전략
