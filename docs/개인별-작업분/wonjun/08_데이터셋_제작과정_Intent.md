# Intent — 가상 공장 데이터셋 제작 과정

가상 공장 데이터셋(`dataset-v2`)을 만든 과정을 단계별로 기록한다. 최신이 위다. 각 단계는 문제 → 기대 결과 → 영향 범위 → 제약 → 열린 질문 → 결과 순서이며, 결과에는 실제로 확인한 것과 확인하지 못한 것을 구분해 적는다. 숫자는 `07_데이터셋_v2_변경내역.md`의 자동 표가 정본이고, 여기에는 과정과 판단을 적는다.

공통 전제: 회사·공장·자산은 가상이다. 제품·버전 번호는 실제 공개 번호를 가정해 배정한 값이다. 원본(`docs/datasets/manufacturing-mes-20261022/`)은 건드리지 않고 파생 파일을 만든다. DB는 건드리지 않는다. 생성은 시드(20261024)로 재현된다.

## 2026-10-25 · 12단계 — 실제 공장·OT·취약점 데이터셋 전수 조사

### 문제
- 데이터셋의 구성·분포가 대부분 제 가정이다. 실제 공개 자료로 보정할 근거를 찾아본 적이 없다.

### 기대 결과
- 공개 데이터셋 중 실제 공장 구조, 자산, 통신, 패치 분포, 공지 소스에 쓸 만한 것과 못 쓰는 것을 구분하고, 데이터셋에 반영할 항목을 정한다.

### 영향 범위
| 구분 | 내용 |

| 영향 없음 | 생성기, 데이터, DB |

### 제약
- 에이전트 4개가 분야별로 조사하고, 핵심 한 건(NIST SP 1800-10)은 PDF를 직접 내려받아 확인한다. 라이선스가 불명확한 자료는 복제하지 않고 구조·분포·어휘만 참고한다. 로그인·가입이 필요한 곳은 사용자가 한다.

### 결과
- **결론:** 제조사·모델·펌웨어·패치 연령이 있는 실제 공장 자산대장은 공개 데이터에서 확인하지 못했다. 오더·LOT·교대·가동중단·정비가 모두 있는 공개 제조 데이터도 확인하지 못했다.
- **가장 쓸모 있는 것:** 취약점 소스 중 Siemens CSAF(기계가 읽는 영향 버전 범위), CVE List v5, NVD. 구조 참고로는 NIST SP 1800-10(직접 열람: 엔지니어링·운영·감독 LAN·DMZ, 이력 서버, AD 이중, NTP, 로봇, PLC 승인 펌웨어)과 MITRE ATT&CK for ICS 자산 18종, 4SICS·ICS-pcap.
- **분포 보정:** Lansweeper 2026(제조 Win10 약 18%, 2차 출처), DBIR(중앙값 32일)과 Tenable(평균 100~400일) → 긴 꼬리, Wang 2017(ICS 60일 내 30% 미만 갱신). OT의 Win7/XP 비율은 확보 못 함.
- **실패·한계:** Kaggle·KAMP·4TU·AI Hub·Schneider 등은 본문이나 목록을 못 봤다. 일부 수치는 검색 요약·2차 기사다.
- **남은 일:** 반영 항목 결정, KAMP 확인, 4SICS 분석.

## 2026-10-25 · 14단계 — 참고 기업 연혁 기반 개설 연도, 10년 주기 장비 교체, MES 도입 시기

### 문제
- 사용자 요청: 가상 회사가 연결한 실제 참고 기업의 개설 연도를 찾아 장비를 언제쯤 교체했을지 판단해 정리할 것. 사용자 지시: 장비는 보통 10년 주기로 바뀌고 안 바뀌는 경우도 많으며, MES는 도입한 지 얼마 안 된 회사가 많다.
- 이전 단계의 라인 개설 연도는 2018~2025 가정이라 20~30년 된 공장의 장비 세대를 담지 못한다.

### 기대 결과
- 참고 기업의 공개 연혁에 맞춘 개설 연도, 10년 주기와 미교체를 반영한 장비 구성, MES 도입 이후에 설치된 수집·MES 계층. 구형 제품과 지원 종료 OS가 현실처럼 남아 있다.

### 영향 범위
| 구분 | 내용 |
|---|---|
| 시스템·파일 | `generate_v2.py`(`plan_growth` 연도 지정, `apply_line_profiles` 교체 주기·구형 제품, `apply_mes_year`, 서버 설치 연도), `v2_rules.py`, `research_versions.json`(Windows XP 종료일), 엑셀, `10_참고기업_연혁과_교체시기.md`(신규) |
| 영향 없음 | 원본, DB, AI4I 값 |

### 제약
- 사용자 지시: Gemini Flash 활용(이전 단계부터 계속). 참고 기업은 업종 참고용이며 실제 기업 정보 확인이 아니다. 확인하지 못한 연도·투자액은 비워 둔다.

### 열린 질문
| # | 질문 | 상태 |
|---|---|---|
| 1 | 라인 개설 연도 배치, 교체 주기·확률, MES 도입 연도는 가정이다 | 사용자 확인 필요 |
| 2 | 디아이씨 공식 연혁(이미지)·daeil.pdf의 한글 | 확인 못 함 |
| 3 | 구형 제품 이름(FANUC 0i-MD 등)의 출시·단종 시기 | 검증 안 함 |

### 결과
- **조사(에이전트 1개 + Microsoft 수명주기 원문):** 대동기어 연혁 직접 열람(1973 설립, 1995 공장 이전, 2005 MES 구축완료 등), 서진오토모티브 연혁 직접 열람(1966 창립, 1994~95 시화 신공장 등), 디아이씨는 설립 1976만 PDF 원문에서 확인하고 나머지는 snippet. Windows XP 지원 종료 2014-04-08, WES7 ESU 3년차 2023-10-10을 원문에서 확인.
- **구현:** 사이트별 개설 연도 목록(참고 사건 근처), 장비 교체 주기(함수 초안 Gemini Flash: 입력 2,297·출력 1,418토큰, 검토·통합), 구형 제품과 2008년 전 모델 미상, 연도별 OS, MES 도입 연도 이후 설치, 기반 서버 교체, WES7 HMI는 2017년 이전 라인만.
- **검증:** 세 회사 검사 통과. 2008년 전 도입인데 모델이 적힌 제어기 0개. **발견한 오류와 수정:** 1995년 라인에 2000년대 제품명이 붙어 있어 2008년 전은 모델 미상으로 바꿨고, 구형 라인의 "새로 추가된 설비"에 현행 제품이 붙던 것을 막았으며, 라인당 CNC 제품 수 검사를 4종으로 완화했다.
- **남은 일:** 경고 쏠림 해소, 조사 반영 항목 7개 중 남은 것, 가정 값의 현장 확인.

## 2026-10-25 · 13단계 — 라인이 늘어난 과정(세대) 반영, Gemini Flash 활용

### 문제
- 사용자 지적: 라인은 처음부터 다 만들지 않고 2~3개로 시작해 규모가 커진다. 그러면 구세대와 최신 세대의 차이가 크다. 지금은 라인 위치(앞 40%·뒤 20%)로만 시기를 나눠 성장 과정이 없다.

### 기대 결과
- 사이트마다 최초 2~3개 라인이 있고 이후 해마다 라인이 추가된다. 개설 연도·세대에 따라 OS, 제조사 구성, 스위치, 갱신 이력, 대장 품질이 달라진다. 서버·인프라는 최초 개설 시기에 구축된다.

### 영향 범위
| 구분 | 내용 |
|---|---|
| 시스템·파일 | `generate_v2.py`(`plan_growth` 신규, `apply_line_profiles` 교체, 세대별 갱신·대장 품질, 서버 구축 연도, 검사), `v2_rules.py`, `export_xlsx.py`, `render_report.py` |
| 영향 없음 | 원본, DB, AI4I 값 |

### 제약
- 사용자 지시: Gemini Flash를 써서 토큰을 덜 쓰며 구성할 것. Gemini는 전달한 텍스트에만 답하므로 함수 초안만 맡기고 검증·통합은 직접 한다.
- 시기별 제조사 가중치와 개설 연도는 가정이다. 840D sl의 2024-10 단종일은 유통사 글(2차 자료)이다.

- **구현:** `plan_growth`(Gemini 초안 입력 1,027·출력 1,468토큰, 규칙 대조·단위 검사 후 주석만 정리해 통합), `apply_line_profiles` 교체(Gemini 초안 입력 1,463·출력 913토큰), 세대별 갱신 확률(구 35%·중 20%·신 10%)·대장 부실도(구 1.8배·신 0.4배), 리트로핏과 OS 재설치 표시, 서버 구축 연도.
- **검증:** 세 회사 검사 통과(새 검사: 최초 라인 2~3개, 개설 연도 비감소, 설치 연도가 개설 연도 이후). 구세대와 신세대 비교: VMB 구세대 CNC는 Siemens 840D sl 20·FANUC 14, 신세대는 FANUC만(840D sl 없음). Windows 11 비율 구/중/신 0%/0%/약 86~94%. 한 번도 확인 안 함 비율 구 약 14~15% → 신 0~4%.

- **남은 일:** 경고 쏠림(자산 약 55% 영향 범위) 해소, 실제 데이터셋 조사의 반영 항목 7개, 공정 목록·통신 밀도 보강.

## 2026-10-24 · 11단계 — 공정(라인) 유형별 구조 재구성

### 문제
- 12·16·24개 라인이 모두 같은 구성(자산 24~26개, 공정 목록 한 가지)이다. 제품이 달라도 같고, 공정과 설비가 연결되지 않는다(소재 투입·디버링·포장에는 설비가 없음).
- CNC마다 Windows 조작 PC가 하나씩 있고, 중요도는 거의 전부 high, OT 제약은 전부 같다. 통신은 자산당 1건도 안 된다.

### 기대 결과
- 라인 유형(가공 / 세척·검사 / 조립·포장)마다 설비 종류와 수가 다르다. 소재 투입·디버링·포장도 PLC를 가진다.
- CNC는 내장 패널을 쓰고 Windows HMI는 라인당 1~2대다. 제조사 번들 OS는 일반 패치 대상과 구분해 표시한다.
- 중요도는 병목 공정과 이중화 여부로, 작업 제약은 협력사 관리·무정지 여부로 나뉜다.
- OT는 도입 시점 빌드를 유지하고 일부만 점검 때 갱신한다. 사무 PC는 월 패치로 최근 빌드 중심이다.

### 영향 범위
| 구분 | 내용 |
|---|---|
| 사용자 | 이 데이터로 화면·수집기·매칭을 시험하는 팀원 |
| 시스템·파일 | `dataset-v2/generate_v2.py`, `v2_rules.py`, 출력 JSON·엑셀. 자산·설비·라인·대장·설치 목록·통신·스위치 포트 결합·작업지시 관측의 연결을 함께 고쳐야 한다 |
| 영향 없음 | 원본 JSON, DB, 앱 코드, AI4I 원본 값 |

### 제약
- 사용자가 정한 방향: 라인 유형은 3유형(제가 가정, "가정"으로 표시), CNC는 내장 패널 + 라인당 공용 HMI 1~2대, 중요도는 병목 공정 + 이중화 여부, 패치 정책은 OT 도입 시점 빌드 유지·사무 PC 월 패치.
- AI4I 관측값(공정 가공 데이터)은 원본 값을 그대로 둔다. 가공 라인 CNC에만 붙인다.
- 새 제품의 모델·버전을 임의로 만들지 않는다(미상으로 둔다).
