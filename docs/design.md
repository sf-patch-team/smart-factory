# 디자인 기획: smart-factory

> 작성 2026-10-22 · 상태: 초안(승인 전) · 근거: 전역 `design-rules`, `design-styles/clean`(참고용), `ui-ux-pro-max --stack nextjs`·`--domain ux`
> 사용자 기본 요구: **단순하고 예쁘고 깔끔하게.** 스타일 자료는 제3자 참고 자료이며 우리 규칙이 우선한다.

## 1. 스타일 선택
| 후보 | 특징 | 이 프로젝트에 | 판단 |
|---|---|---|---|
| **Clean** | 여백 넉넉, 색 제한, 읽기 쉬운 글 | 표·상태가 많은 업무 화면과 잘 맞음 | **추천** |
| Minimal | 더 절제, 큰 제목 | 정보가 많아 너무 비면 불편 | 보류 |
| Flat | 주황 강조색 | 위험(빨강)·경고(주황)와 색이 겹침 | 제외 |

→ **Clean**으로 한다. 바꾸고 싶으면 이 표만 고치면 된다.

## 2. 색 (토큰 한곳에서 정의, `src/app/globals.css`)
강조색은 **파랑 하나**(주 버튼·선택). 빨강·주황·초록은 **상태 표시에만** 쓴다.

| 토큰 | 라이트 | 다크 | 쓰는 곳 |
|---|---|---|---|
| `--bg` | #FFFFFF | #0F172A | 바탕 |
| `--surface` | #F8FAFC | #1E293B | 카드·표 헤더 |
| `--border` | #E2E8F0 | #334155 | 선 |
| `--text` | #111827 | #F1F5F9 | 본문 |
| `--muted` | #475569 | #94A3B8 | 보조 글 |
| `--accent` | #2563EB | #60A5FA | 주 버튼·링크 (글자 대비 확보 위해 Clean 원색보다 진하게) |
| `--danger` | #B91C1C | #F87171 | 위험·반려·못 읽음 |
| `--warn` | #B45309 | #FBBF24 | 경고·처리 중·재검토 |
| `--ok` | #15803D | #4ADE80 | 완료·읽음 |

- 글자색과 바탕의 대비는 4.5:1 이상을 목표로 한다(구현 뒤 확인).
- 본문 `body`에 배경색을 명시한다.

## 3. 글꼴·간격·모서리
- **글꼴: 시스템 글꼴**(`system-ui`, `Apple SD Gothic Neo`, `Malgun Gothic`, 산세리프). 외부 글꼴·CDN을 쓰지 않는다(현장 PC·오프라인).
- 크기: 12 / 14 / 16 / 20 / 24 / 32. 본문 16, 표 14. 숫자 칸은 `font-variant-numeric: tabular-nums`.
- 간격: 8 기준(8·16·24·32). 모서리 8, 작은 칩 4. 한글은 `word-break: keep-all`.

## 4. 레이아웃
- **넓은 화면:** 왼쪽 메뉴(담당자 4개, 관리자는 "관리" 묶음 추가) + 본문. 본문 위에 **받은 시각 표시줄** 한 줄.
- **폰 너비(375px):** 하단 탭 4개(관리자는 5번째 "관리"), 좌우 여백 16px 이상, 가로 스크롤 없음. 표는 카드 목록으로 바꿔 보여 준다.
- 모든 목록은 **빈 상태에도 표 틀을 유지**하고 "아직 없음"만 안내한다.

## 5. 핵심 부품
| 부품 | 규칙 |
|---|---|
| 상태 칩 | **점 + 글자**(색만으로 구분하지 않음), 너비 고정(최소 72px) |
| 받은 시각 표시줄 | `읽음 / 내용 없음 / 못 읽음` + 마지막 성공 시각, 높이 고정 |
| 점수 구성 | 점수 숫자 + 4개 항목(기한 초과·랜섬웨어·중요도·최근 등록)을 같은 줄에 |
| 표 | 행 높이·안쪽 여백 통일, 제목 줄 고정 높이, 숫자 오른쪽 정렬 |
| 버튼 | 높이 40px 이상, 주 버튼은 화면당 1개, 위험 동작은 한 번 더 확인 |
| 저장 피드백 | 누르면 "저장 중…" → "저장했습니다"/오류 문구(결과가 화면에 남음) |
| 모달 | 제목·내용·버튼 3단, 닫기 키보드 지원, 포커스 이동 |

**상태 칩 매핑:** 신청(회색) · 승인(파랑) · 처리 중(주황) · 완료(초록) · 반려(빨강) · 보류(회색+‖ 표시) · 완화 조치(주황). 데이터 상태: 읽음(초록) · 내용 없음(회색) · 못 읽음(빨강).

## 6. 글쓰기
쉬운 한국어, 짧게. 버튼은 동사("신청하기", "승인하기", "해당 없음으로 닫기"). 오류는 **무슨 일 + 어떻게 하면 되는지**. 예: "받아오지 못했어요. 이전 데이터를 보여 드려요. 관리자에게 다시 받아오기를 요청해 주세요."

## 7. 접근성
키보드로 모든 기능 사용, 포커스 표시, 폼 입력에 `label`, 상태 변화는 `role="status"`로 한 번만 알림(숫자만 읽히지 않게 문장으로), 라이트/다크 모두 대비 확인.

## 8. 끝난 뒤 확인 (QA 연결)
- 넓은 화면과 375px에서 캡처: 가로 스크롤·잘림·겹침 없음
- 라이트·다크 모두 확인, 빈 상태·오류 상태 각 1회
- 시험 모드 표시와 "못 읽음" 상태가 눈에 띄는지
- 확인 못 한 환경은 QA 시트의 사람 확인 목록으로 넘긴다
